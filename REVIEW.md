# REVIEW.md

## Starter Code Review

I reviewed the starter `app/main.py` against the API contract, attendance business rules, MongoDB data model, concurrency requirements, and query-performance expectations. The following issues were identified and addressed in the updated implementation.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes()` | The helper calculates the delay relative to a shift start but does not explicitly handle timezone conversion or the attendance date. | Test punches before shift start, exactly at the 10-minute grace boundary, and after the boundary. | Added timezone-aware calculation against the scheduled shift start and applied the strict greater-than-10-minute rule. |
| 2 | `compute_work_hours()` | Built-in `round()` does not implement the required half-up rounding rule for all boundary values. | Test work durations whose hour values fall on rounding boundaries. | Used `Decimal` with `ROUND_HALF_UP` to calculate work hours to two decimal places. |
| 3 | `compute_overtime()` | The starter always constructs shift end on the attendance date, so overnight shifts can have incorrect overtime calculations. | Test a shift that starts on one day and ends after midnight. | Added `shift_end_datetime()` to determine the correct shift-end date and applied the 30-minute overtime threshold. |
| 4 | MongoDB client initialization | The starter does not explicitly configure timezone-aware UTC datetimes, and its default timestamp handling can depend on the machine's local timezone. | Store and retrieve timestamps and compare the results with the expected UTC and epoch-millisecond values. | Configured `MongoClient` with `tz_aware=True` and `tzinfo=UTC`; added helpers for UTC timestamps and epoch-millisecond conversion. |
| 5 | `create_employee()` | Checking for a duplicate employee code before inserting is a race-prone check-then-insert operation. `created_at` also uses a naive local datetime. | Send concurrent requests using the same employee code, and inspect the stored creation timestamp. | Added the unique `uq_employee_code` index, handled `DuplicateKeyError` with HTTP 409, and stored a UTC creation timestamp. |
| 6 | `list_employees()` | Pagination uses `page * page_size` as the skip value, which skips the first page's records. The total count ignores the department filter. | Request page 1 with a small page size and compare filtered results with the reported total. | Corrected the skip formula, applied the same filter to the count, validated pagination parameters, and added stable sorting by employee code. |
| 7 | `punch_in()` | The starter does not handle an unknown employee before accessing their shift details. It also treats epoch timestamp `0` as missing and converts timestamps using local-time behavior. | Punch in with an unknown employee code, submit timestamp `0`, and test timezone-sensitive timestamps. | Added employee existence validation, explicit `None` checks, epoch-millisecond validation, and timezone-safe conversion. |
| 8 | `punch_in()` and attendance indexes | The duplicate attendance check and insert are separate operations, so simultaneous punch-ins can both pass the check. | Send simultaneous punch-in requests for the same employee and attendance date. | Added the unique `uq_attendance_employee_date` compound index and translate duplicate-key errors into HTTP 409. |
| 9 | `punch_in()` and attendance date helpers | The starter does not account for the employee's shift when determining the attendance date and does not fully validate the requested attendance status. | Test an overnight shift, an early-morning punch belonging to the previous shift date, and invalid punch-in statuses. | Added `attendance_date()` and validated punch-in statuses using a Pydantic `Literal`. |
| 10 | `list_attendance()` | The starter loads all matching records into Python, sorts them in memory, and paginates afterward. This is inefficient for a large dataset. | Query a large attendance collection and inspect memory usage and query execution statistics. | Moved filtering, sorting, and pagination into MongoDB and added supporting attendance indexes. |
| 11 | `list_attendance()` | The starter does not validate pagination inputs, does not validate date ranges consistently, and exposes MongoDB's internal ID through an `id` field. | Submit invalid page values or malformed dates, and inspect the returned JSON. | Added pagination constraints, shared date-filter validation, deterministic sorting, and response serialization that excludes `_id`. |
| 12 | Missing `POST /attendance/punch-out` | The required punch-out endpoint is absent from the starter. | Call the required route and observe that it is unavailable. | Implemented employee and open-record checks, timestamp and duration validation, work-hour and overtime calculations, and an atomic conditional update to prevent two concurrent punch-outs from succeeding. |
| 13 | Missing `PATCH /attendance/{emp_code}/{date_str}` | The starter does not implement attendance regularization, status validation, or change history. | Call the route and test invalid timestamps, invalid status/punch combinations, and concurrent updates. | Implemented regularization validation, change-history entries, recalculation of attendance fields, and a compare-and-set update that returns HTTP 409 if the record changes concurrently. |
| 14 | Missing `GET /analytics/employees/{emp_code}/monthly` | The required employee monthly attendance summary is absent. | Request a monthly summary and observe that the route is unavailable. | Implemented a MongoDB aggregation pipeline for monthly attendance totals and calculated applicable working days using the employee's joining date. |
| 15 | Missing `GET /analytics/departments/summary` | The department summary is absent. Aggregating only attendance records would omit employees who have no logs from headcount. | Request a department summary for a department containing an employee without attendance records. | Added a MongoDB pipeline using `$unionWith` to combine attendance statistics with employee headcount, including departments without attendance logs. |
| 16 | Missing `GET /analytics/leaderboard/late` | The required late-comer leaderboard and tie handling are absent. | Request a leaderboard with multiple employees tied at the cutoff rank. | Added database-side ranking with `$rank`, filtered by rank rather than limiting rows before ranking, and used employee code for deterministic display ordering. |
| 17 | Missing `GET /analytics/departments/{department}/trend` | The required daily attendance trend is absent. Returning only dates with logs would omit calendar days without attendance records. | Query a date range containing weekends and dates without logs. | Added a MongoDB aggregation using `$densify`, daily headcount, attendance-rate calculations, and `$setWindowFields` for the seven-day moving average. |
| 18 | Missing `GET /admin/explain/{endpoint}` | The starter does not provide the required execution-plan inspection endpoint. | Request an explain plan and observe that the route is unavailable. | Added an explain endpoint using MongoDB `executionStats` and shared query/pipeline builders so the explain operation uses the corresponding endpoint's filters and query logic. |
| 19 | Application startup and index creation | The starter does not create the indexes needed to enforce uniqueness and support the expected query patterns. | Start the application against a database without the required indexes, inspect its indexes, and test duplicate records. | Added idempotent index creation at startup for employee identity, attendance uniqueness, employee department/join-date queries, and attendance date/history queries. |
| 20 | `/health` | The starter returns HTTP 200 without checking whether MongoDB is reachable, so it can report healthy while the database is unavailable. | Stop MongoDB and request `/health`. | Added a MongoDB ping and return HTTP 503 when the database is unavailable. |

## Items Reviewed and Not Considered Defects

- **MongoDB `_id`:** MongoDB automatically assigns `_id` to stored documents. Its presence in the database is normal; the API should not expose it as the employee's public identity.
- **One attendance record per employee per date:** A unique compound index on `(emp_code, date)` is appropriate for enforcing this requirement and preventing concurrent duplicate inserts.
- **Employees without attendance logs:** These are valid employees and must still be counted in department headcount when eligible.
- **Calendar dates without attendance logs:** Missing attendance records should not cause dates to disappear from the department trend.
- **Environment configuration:** Using `MONGO_URI` and `MONGO_DB` is appropriate. `load_dotenv(override=False)` preserves environment variables supplied by the operating system over local `.env` values.
- **MongoDB aggregation:** Database-side aggregation is appropriate for analytics on the larger evaluation dataset and avoids loading entire collections into Python for calculations.
- **Optional punch timestamps:** Allowing punch endpoints to use the current UTC time when `punched_at` is omitted is intentional, provided supplied timestamps are validated and converted consistently.
